# Architecture Revision 2 - Security

Proposed controls, not tested security claims. Numerical defaults are **PROPOSED - UNMEASURED UNTIL BENCHMARKED**. No customer code runs; trusted application compromise remains outside the tenant-isolation guarantee.

## Exactly one tenant-context mechanism

`tenant_transaction(workspace_id, authorized_context)` is the only entry point. It starts an outermost `transaction.atomic(durable=True)` using a role-appropriate connection, executes parameterized `set_config('app.workspace_id', validated_uuid, true)` (the transaction-local equivalent of SET LOCAL), then performs all tenant SQL and eager DTO serialization, and commits/rolls back before returning. Nested calls may reuse the same workspace context within this wrapper but cannot change tenants; an unrelated enclosing transaction is rejected. `ATOMIC_REQUESTS=False`; Django autocommit remains on outside the wrapper. No bare SET LOCAL outside an active transaction, no session-level tenant SET, no reset-on-close scheme.

Global authentication/session validation and the membership bootstrap are narrow explicit non-tenant operations. A reviewed membership lookup function accepts the authenticated principal and candidate workspace, returns only authorized role/status/revocation epoch, and grants no arbitrary tenant reads. Set tenant context from that checked result, recheck action/resource membership in the transaction. Worker context comes only from claimed job identity and control guard, never from task JSON/model content. Workers cannot read membership or token/session tables; guarded DB functions expose only eligibility, not auth records. Revocation changes a dispatch-control epoch atomically; subsequent guards refuse stale eligibility.

All tenant reads/writes, including GETs, background heartbeat/reaper/reducer/retention, use the wrapper. Return materialized DTOs; lazy QuerySets, deferred model attributes, template ORM calls, streaming database iteration and async work escaping the transaction are forbidden. No network calls inside the wrapper. OIDC exchange happens outside and persists its minimal result in a later appropriate transaction.

Initial pooling choice: Django/psycopg built-in connection pooling, CONN_MAX_AGE=0, no second external/session pooler. Persistent physical connections are deliberately reused in tests. Pool checkout validates no unexpected tenant setting; commit/rollback removes LOCAL state; unexpected residual session context quarantines/closes connection and alerts. Startup refuses nonempty tenant role/database defaults. A switch to PgBouncer or other pooler requires a separate compatibility review and test, not an alternate supported mechanism.

Development/test DB execution guard refuses tenant ORM/raw SQL unless inside the wrapper with matching DB current_setting and active transaction. Only enumerated global-auth/health/bootstrap functions bypass the guard; unknown raw SQL is denied until registered/reviewed. Production RLS deny-default remains enforced if application guard fails. Real-role TransactionTestCase-style integration tests exercise commit, rollback, exceptions, connection reuse, savepoint failure, thread isolation and empty/malformed tenant settings. Do not rely only on Django TestCase's enclosing transaction.

## Roles and cross-tenant surface

Web/worker are non-owner, non-superuser, no BYPASSRLS, DDL, TRUNCATE, role management or arbitrary function creation. Enable and FORCE RLS with both USING and WITH CHECK. Composite FKs and generic errors protect relationships and side-channel details; uniform 404 does not claim constant-time nonexistence. Migration/bootstrap credentials are short-lived and never mounted on application containers. Managed backup/restore credentials are outside the app host. Retention has bounded deletion permissions, not general customer browsing.

Enumerated SECURITY DEFINER API: `authorize_membership_context`, `list_eligible_work_ids`, `claim_work`, `list_expired_job_ids`, `list_due_reduction_ids`, `list_retention_workspace_ids`, `dispatch_control_guard`, and scoped platform-budget/counter functions required by the lock protocol. List functions return IDs/minimal due timestamps only and do not lock candidates. Claim is the reviewed Job-first transaction operation; no arbitrary SQL/filter/order arguments. Functions have fixed safe search_path, fully qualified objects, no dynamic SQL, revoked PUBLIC execute, role-specific grants and a no-login privileged owner with only necessary table rights. Any added function requires inventory/reviewer approval and negative tests. Narrow functions are a maintenance boundary, not a claim of protection against a malicious DB administrator.

## Identity, browser and auditing

Managed OIDC Authorization Code+PKCE, exact issuer/audience/signature/state/nonce/redirect checks through maintained library; stable issuer+subject identity. Verified invitation target, one-use hashed invitation, no self-selected owner role. Secure/HttpOnly/SameSite=Lax opaque server session, proposed 8-hour absolute/30-minute idle expiry and rotation on login; logout invalidates app session. Recent authentication for member/token/delete/secret actions. CI bearer paths have no cookie fallback; project scopes, keyed token hash, revocation on creator removal. CSRF for cookie mutations; no permissive CORS.

T-004b installs the service-layer atomic audit convention before sensitive mutations: membership, token issue/revoke, publish, start/cancel, quota/retention, delete, operator grants and kill switches all require safe AuditEvent in the same DB transaction. Audit insert failure rolls back action. Sensitive onboarding/bootstrap changes follow the same principle. Audit never records token plaintext or raw diffs containing prompts/secrets. Runtime has insert-only audit rights; DBA tampering is residual.

Escape plain text; never use customer strings as templates/format patterns or mark_safe/HTML-safe output. CSP default-src self, restricted connect-src, no remote images, frame-ancestors none, nonce-only scripts where needed. URL text is not auto-fetched. SDK wire logging, request body logging, auth headers, environ/proc dumps and core dumps are disabled. HTTP/SDK exception canary fixtures cover headers and repr; DEBUG=False does not replace exception scrubbing.

## Operator/debug boundary

Django admin and debug toolbar are absent from deployed INSTALLED_APPS/routes; DEBUG=False and template debug off in staging/production. Startup fails on unsafe debug/admin, empty/wildcard ALLOWED_HOSTS, insecure cookies/CSRF origins, unsupported schema, missing policy, invalid rate card, unavailable required secrets or unsafe DB roles. No customer-accessible shell, eval console, unrestricted /metrics or diagnostic payload endpoint. Local development may use DEBUG only with synthetic data and no real credentials; deployed configuration refuses it.

No routine application/DB shells with customer access. MFA and named least-privilege accounts on cloud, DB, identity and secret consoles. Break-glass: recorded incident and scope, customer consent for support browsing (or documented authorized emergency basis), independent approval, expiring role <=1 hour, restricted bastion/session logging without secrets, query/action audit, revoke and review after use. If the normal audit DB is down, append to separately protected incident audit storage before access, reconcile afterward; no unaudited emergency shortcut. No broad RLS-bypassing credential on web/worker/VM. Automated start checks plus G-18 test both allowed and refused access.

## Secrets and effects

Platform keys only. Environment-separated secret store, root-owned restricted tmpfs files read-only mounted to required process; no image/CLI/committed .env/plain DB values. Worker gets model key and restricted DB role, not cloud/deploy/migration/admin credentials or Docker socket. Web cannot read model key. Known canary redaction is tested but cannot guarantee removal of all customer-pasted/encoded secrets. Provider processing is an intentional external data flow; prompts/schemas/messages may leave the platform.

Non-root containers, read-only root, dropped capabilities, no-new-privileges, reviewed seccomp, no privileged mode/host mounts, bounded tmpfs/RAM/CPU/PIDs, no runtime package installation. Pure simulator has no filesystem/network/database handles. Positive provider request allowlist in EXECUTION_MODEL is enforced before dispatch; fixed CONNECT host alone does not prevent provider-side remote content fetch features.

Network paths and deny tests are in DEPLOYMENT; no direct worker DNS/public/private/metadata/host socket route is allowed. Proxy validates every resolved A/AAAA answer; fixed host:443, no numeric/wildcard/custom destinations. CONNECT cannot inspect encrypted redirects, so redirects are disabled in adapter and path enforcement belongs to the adapter. Gateways cannot act as general TCP routers. Telemetry sanitization and bounded rate/size limits reduce exfiltration; a compromised worker remains a residual risk.

## Privacy and approval

Disclose app/identity/model/telemetry/backup processing and approved regions before first model call. `store=false` is an API setting, not proof of zero retention; selected provider contractual retention/data terms must be recorded in G-15. No unsupported regulated data or certification claim. Follow DATA_MODEL's single retention schedule; backup persistence and downloaded copies are disclosed. External penetration testing remains hardening for bounded invite-only launch, required before open onboarding or paid-customer expansion; no known exploitable leak/false-safe/spend/restore defect may be deferred.
