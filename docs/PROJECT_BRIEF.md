## Purpose and retained scope

Evaluate a declaratively configured, platform-owned text agent loop against reviewed scenarios using in-memory simulated tools. Explain observed behavior, deterministic checks, uncertainty, resource usage and differences between immutable versions. This does not execute or certify the customer's framework, real tools or production deployment. No aggregate reliability score, production failure probability, hidden chain-of-thought, or compliance certification is offered.

Keep Python 3.13, Django 5.2 LTS at an implementation-verified supported patch, a modular monolith, a separate worker from the same build, managed PostgreSQL 17 for data and durable jobs, server-rendered pages and a narrow DRF API. Keep one approved OpenAI adapter, platform-funded credentials, invite-only onboarding, workspace owner/member roles, human-reviewed immutable suites, scoped CI credentials, bounded retries, fenced attempts, auditable control mutations, deletion replay and tested restore. Exact dependency versions and model eligibility must be checked at implementation.

Deferred: remote customer agents, uploaded code, plugins, real integrations, BYOK, custom endpoints, browser execution, local models, production replay, multi-provider failover, paid billing automation and project-private roles. Each high-risk expansion requires a new threat review. Extra hosts, standby DB, object trace storage and a dedicated broker are scale-triggered, not prerequisites.

## Document ownership and terminology

REQUIREMENTS owns numerical limits and ACs; EXECUTION_MODEL owns locks, state machines and accounting; EVALUATION_DESIGN owns verdict/CI truth tables; DATA_MODEL owns tenancy constraints and retention; SECURITY/DEPLOYMENT own controls/topology; TEST_STRATEGY owns verification specifications. Other documents link these contracts instead of inventing variants.

Workspace is the tenant, visibility and budget boundary. SuiteVersion is the single product/model name (replaces baseline TestSuiteVersion synonym). EvaluationRun is the orchestration record (`evaluation_id` in APIs). ScenarioRun is one case/repetition. ScenarioAttempt is a fenced generation. ModelCall records one possible paid dispatch; UsageLedgerEntry records immutable accounting transitions. Execution status, verdict, evidence completeness and evidence availability are different fields. A logical turn is one agent response opportunity; retries are dispatches of the same turn, not new turns. Time is stored in UTC; display follows user settings.
